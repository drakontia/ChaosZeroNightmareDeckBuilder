# 過去 PR からの教訓

## PR #33 — 英語名はシステムIDになる

### 問題

英語名の選択を誤ると、システム全体の参照が壊れる。

装備の `id` フィールドは英語名から導出され、以下すべてで使われる:

- TypeScript データファイルの `id`
- i18n キーのパス (`equipment.weapon.{id}.name`)
- 画像ファイル名 (`{id}.png`)

一度登録した ID を後から変更すると、3箇所すべての修正が必要になる。

### 教訓

> **必ずゲーム内の英語正式名称を確認してから ID を決める。**

- 日本語名から英語名を類推しない
- ゲーム内テキスト・公式ドキュメントの英語表記をそのまま使う
- 変換ルール: スペースをアンダースコアに、すべて小文字、記号は除去

```
"Obsidian Sword"          → obsidian_sword       ✓
"M85 Military Grenade"    → m85_military_grenade  ✓
"Scout's Combat Boots"    → scouts_combat_boots   ✓（アポストロフィを除去）
```

## PR #39 — 防具名の誤記（delicate_collarbone）

### 問題

防具名を誤って登録した（`delicate_collarbone` という誤った英語名）。

- i18n キーと画像ファイル名もすべて間違った名前で作成された
- 修正時に TypeScript・4言語 JSON・画像ファイルすべてを変更する必要があった
- すでに共有されたデッキデータがあると、データの後方互換性も考慮が必要になる

### 教訓

> **最初の1回で正しく登録する。後から直すコストは大きい。**

登録前チェックリスト:

- [ ] 英語名をゲーム内または公式リソースで確認した
- [ ] snake_case 変換が正しい（スペース→アンダースコア、記号除去、全小文字）
- [ ] `id` と `name` キーパスと画像ファイル名が一致している

## PR #34 — 画像ファイルのパス規則

### 問題

画像ファイルを配置したが、`imgUrl` のパスと実際のファイル名・フォルダ名が一致しないケースがあった。

### 規則（再確認）

| 要素             | 規則                          | 例                               |
| ---------------- | ----------------------------- | -------------------------------- |
| フォルダ名       | **複数形**                    | `weapons/` `armors/` `pendants/` |
| ファイル名       | `{id}.png`（`id` と完全一致） | `obsidian_sword.png`             |
| i18n キーの type | **単数形**                    | `equipment.weapon.{id}.name`     |

間違いやすいポイント:

- `imgUrl` のパスは `weapons`（複数形）
- i18n キーの `{type}` は `weapon`（単数形）
- この2つの使い分けは混同しやすい

### 確認コマンド

```bash
# テストで imgUrl パターンを検証
pnpm exec vitest run tests/unit/lib/equipment-data.test.ts
```

---

## まとめ: 最優先で守るべき3つのルール

1. **英語名は公式ソースから取得する**（日本語名からの類推禁止）
2. **ID 決定後は一貫性を保つ**（TypeScript・i18n・画像の3点が同じ `id` を参照）
3. **4言語すべての i18n を同時に更新する**（後から追加すると抜け漏れが起きる）
